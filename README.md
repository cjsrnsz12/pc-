# 냐크로 · PC

마비노기 모바일의 화면을 인식해 입장·전환·보상 처리를 돕는 Windows 10/11용 앱입니다. 게임 화면의 실제 내용 영역은 **가로 800 × 세로 1000**으로 사용합니다.

## 다운로드 및 실행

1. [최신 배포](https://github.com/cjsrnsz12/pc-/releases/latest)에서 **AbyssHelper.exe**를 내려받습니다.
2. 실행 파일을 더블클릭합니다. 별도의 Python 설치나 CMD 창이 필요하지 않습니다.
3. 게임을 실행하고 앱이 마비노기 모바일 창만 찾아 자동 선택합니다.
4. **게임 창 자동 맞추기**를 누르고 목적지·난이도를 선택합니다.
5. **시작(F8)**을 누른 뒤 게임 창을 클릭합니다. 중지는 **F9**입니다.

게임 화면이 다른 창에 가려지지 않도록 배치하세요. 다른 앱으로 전환하면 인식과 입력을 보류하고, 게임으로 돌아오면 이어갑니다. 최소화·크기 변경·창 종료 시에는 중지합니다. UI 크기·레이아웃이 참고 이미지와 달라 인식되지 않으면 기록에 안내하고 입력을 보류합니다.

게임 창 자동 맞추기는 클릭할 때마다 게임을 다시 검색하고, 최소화·최대화 상태를 복원합니다. 전체 화면이면 게임 활성화 후 Alt+Enter를 한 번 보내 전환을 시도하고, 상태를 다시 읽어 필요하면 창 스타일을 보정한 뒤 실제 내용 영역을 800×1000으로 맞춥니다. 제목 표시줄과 최소화·최대화·닫기 버튼은 유지하며, 800×1000은 제목 표시줄을 제외한 게임 내용 영역입니다. 게임 내용과 제목 표시줄이 모두 보이는 위치로 조정합니다. 아래쪽 테두리만 작업 표시줄 영역에 겹치는 경우는 허용하지만 게임 내용은 가리지 않습니다. 공간 자체가 부족하면 제목 표시줄을 숨기는 대신 해상도·작업 표시줄 설정 안내를 표시합니다. 크기를 다시 측정해 최대 3회 보정합니다. 실패하면 모니터 공간 부족, Windows 오류, 게임의 화면 모드 고정 여부를 안내하고 현재 크기·DPI·스타일을 app.log에 기록합니다. 게임이 독점 전체 화면 전환을 지원하지 않거나 해상도를 계속 되돌리면 자동 적용을 보장할 수 없습니다. 여러 게임 창이 있으면 목록에서 고른 창을 유지합니다. 게임 제목이 `마비노기 모바일` 또는 `Mabinogi Mobile`인 창만 대상으로 하며 브라우저·일반 마비노기·런처·문서 창은 제외합니다.

## 권한 안내

**게임 창 자동 맞추기**와 **시작**을 누르면 앱과 게임이 각각 일반·관리자 권한인지 확인합니다. 게임만 관리자라면 필요한 권한을 안내하는 알림창을 표시합니다. **권한 확인** 버튼으로도 현재 상태를 볼 수 있습니다.

알림창에 **관리자 권한으로 다시 실행**이 표시되면 버튼을 누른 뒤 Windows 사용자 계정 컨트롤(UAC)의 **예**를 선택하세요. 직접 실행하려면 앱을 종료하고 EXE를 우클릭 → 관리자 권한으로 실행을 선택합니다. 앱이 임의로 관리자 권한을 획득하거나 Windows의 승인을 대신하지 않습니다. UAC를 취소하면 기존 앱을 유지합니다.

Windows 오류 5는 액세스 거부입니다. 권한 차이가 확인되지 않았거나 이미 관리자라면 게임·보안 정책 등 다른 원인이 있을 수 있다고 안내합니다. 업데이트 폴더의 쓰기 권한 오류에는 앱을 사용자 폴더로 옮기거나 다른 저장 위치를 고르는 방법을 안내합니다. 화면 캡처를 위한 별도의 Android 접근성 권한이나 휴대폰 권한은 필요하지 않습니다.

## 앱 화면

화면 높이에 맞춰 창 크기를 조정하고 둥근 손잡이의 스크롤바를 지원합니다. 화살표 없이 스크롤·트랙 클릭·드래그를 사용할 수 있고 마우스 오버는 민트색, 드래그는 보라색으로 강조합니다. 업데이트 소식·권한 확인은 하단에 고정해 창을 줄여도 접근할 수 있습니다. 보라·민트 그라데이션 헤더, 은은하게 떠 있는 심볼과 전용 앱 아이콘을 적용했습니다. 체크박스는 X 대신 ✓로 표시하며 체크·마우스 반응은 약 0.15초 동안 부드럽게 전환합니다. 선택·비활성화·마우스 오버에서도 어두운 배경과 읽기 쉬운 글씨를 유지합니다. 화면 장식과 애니메이션은 게임 인식·클릭 설정에 영향을 주지 않습니다.

## 구현된 순서

- 일반 화면: 이동하지 않는 상태를 연속 4초 확인 → 메뉴 → 어비스 → 목적지 이름을 찾아 클릭. 일반 메뉴와 콜라보 배너 메뉴를 모두 지원하며 메뉴 패널에서 실제 어비스 아이콘·글자의 위치를 찾아 클릭합니다. 닫기 버튼과 같은 줄의 필드 보스 또는 레이드도 함께 확인합니다. 배너 때문에 행이 이동해도 과거 좌표를 그대로 누르지 않으며 실제 클릭 좌표를 실행 기록에 남깁니다.
- 입장 설정: 던전 이름 → 함께하기 선택 → 선택 난이도 → 우연한 만남 초록색 ON 확인 → 입장하기.
- 이미 켜진 우연한 만남을 다시 누르지 않습니다. 확인되지 않은 조건에서는 입장하지 않습니다.
- 입장 대기 및 검은 로딩 화면에서는 메뉴를 열지 않습니다.
- 전투 도중 시작해도 스킬 UI가 확인되면 전투 상태를 유지합니다. 전투에서 잠깐 멈춰도 메뉴를 열지 않습니다.
- 장면 넘기기 버튼 → 한 번 클릭 → 보스 전투.
- 던전 클리어와 화면 터치 안내가 모두 나타나면 중앙 한 번 클릭.
- 어비스 솔로 모드는 보상 화면에서 다시 하기. 파티 모드는 다른 던전 가기 → 설정한 목적지 → 입장하기로 반복합니다. 세 던전에 같은 흐름을 적용하며 입장 조건은 매번 다시 확인합니다.
- 어비스·레이드 공통: 행동 불능과 주황색 여기서 부활 글씨 확인 후 부활. 내 체력 감소 예시 수준에서 F1 회복물약을 확인해 사용하며 입력 간격은 10초입니다.
- 우연한 만남 대기부터 로딩 완료까지 던전 입장 중으로 유지.
- 협동 미션 완료창은 확인을 누르고 기존 진행 상태를 유지.
- 음식 아이콘이 나타나면 한 번 클릭. 아이콘이 사라질 때까지 중복 클릭하지 않습니다.
- 일반 버튼은 반응이 없으면 2.5초 간격으로 최대 3회 시도한 뒤 중지. 중앙 클릭·장면 넘기기·음식은 한 번만 클릭합니다.

목적지는 허상의 정박지·광기의 동굴·흩어진 물길입니다. 허상의 정박지 기본 난이도는 매우 어려움이며 매우 어려움2와 구별합니다. 다른 두 던전의 기본값은 제공된 목록 화면을 따라 어려움·입문으로 두었고 앱에서 바꿀 수 있습니다. 솔로·파티 모두 함께하기·난이도·우연한 만남 상태를 확인합니다. 플레이 모드에 따라 보상 화면의 반복 경로를 다르게 선택합니다.

## 업데이트 안내

앱 시작 시와 실행 중 5분마다 이 저장소의 정식 GitHub Release를 확인합니다. 메인 화면의 **업데이트 소식** 또는 새 버전 자동 감지 시 작은 별도 창에서 **지금 업데이트 / 업데이트 내용 / 나중에**를 선택합니다. **지금 업데이트**는 바로 다운로드·설치·재실행을 시작합니다. **업데이트 내용**은 색상별 변경 사항을 보여 주는 상세 창을 엽니다. 상세 창의 설치 버튼도 하단에 고정되어 긴 글에 밀려 숨겨지지 않습니다. 두 창 모두 모니터의 작업 영역과 제목 표시줄 높이를 고려해 화면 안에 배치합니다.

알림창에는 **해당 최신 버전의 변경 사항만** 표시합니다. **새 기능은 초록색**, **개선은 파란색**, **버그 수정은 주황색**으로 구분합니다. 이전 버전 내역은 알림창에 합쳐 표시하지 않습니다. 현재 최신 버전인 경우에도 이번 버전의 변경 사항을 확인할 수 있으며 설치 버튼은 비활성화합니다.

업데이트 버튼을 누르면 즉시 연결 중·진행률·파일 검증·설치 준비 상태를 표시하고 다운로드·교체·재실행을 진행합니다. 실패·취소 후에는 다시 시도할 수 있습니다. 숨겨진 알림창은 다시 보이는 위치로 가져오고, 남아 있는 설치 상태 때문에 버튼을 조용히 무시하지 않습니다.

매크로는 중지되며 설정·기록은 유지합니다. 새 버전 UI의 시작 확인에 실패하면 이전 파일로 복구를 시도합니다. 폴더 쓰기 권한·디스크 공간 부족 등 실패 원인을 안내합니다. CMD나 PowerShell 창은 사용하지 않습니다. **파일만 다운로드**로 직접 저장할 수도 있습니다.

네트워크 연결 없이도 앱의 기본 동작은 사용할 수 있습니다. 저장소가 공개되어 있으므로 사용자의 GitHub 로그인·토큰을 앱에 저장하지 않습니다.

## 기록과 설정

`%LOCALAPPDATA%\AbyssHelper`에 설정과 실행 기록을 저장합니다. 앱의 **기록 폴더** 버튼으로 열 수 있습니다. 로그는 순환 저장하며 게임 화면이나 채팅 이미지를 업로드하지 않습니다.

## 검증 범위

제공된 스크린샷에 대한 화면 분류와 상태 전환 단위 테스트를 포함합니다. Windows 빌드에서는 생성된 EXE의 GUI 서브시스템과 시작·UI·참고 이미지 로딩을 검사합니다. 실제 별도 보조 EXE로 테스트 앱의 종료를 기다려 교체하고 새 UI의 시작 확인까지 이어지는 자동 업데이트 전체 경로도 검사합니다. 실제 게임에서의 인식률, 특정 캐릭터의 대기 모션, 게임의 입력 허용 여부는 사용자의 PC에서 확인이 필요합니다. 화면의 정지 여부는 이름표·중앙 군중 영역·HUD의 영향을 제외한 여러 배경 영역과 미니맵 지형의 움직임으로 추정합니다. 서로 다른 영역에서 고정 배경이 충분히 확인될 때만 4초 정지 타이머를 진행합니다. 카메라가 캐릭터를 따라 이동하는 일반 시점을 기준으로 하며, 배경이 대부분 가려지거나 판정 근거가 부족하면 메뉴를 누르지 않고 대기합니다.

이 버전은 안내된 UI 흐름을 자동화합니다. 이동·몬스터 탐색·별도 스킬 입력·부활은 아직 구현하지 않았으며 게임의 자동 전투 기능을 사용합니다. 광기의 동굴·흩어진 물길의 상세 화면은 제공되지 않아 인식 조정이 추가로 필요할 수 있습니다. 던전 이름을 확인하지 못하면 입장을 보류합니다.

## 개발 및 빌드

Python 3.12를 권장합니다. `python -m pip install -r requirements.txt`, `python -m pip install pytest pyinstaller==6.16.0` 후 `python -m pytest -q`로 테스트합니다. Windows에서 `python build_windows.py`로 `dist/AbyssHelper.exe`를 생성합니다. 소스 실행은 `pythonw Start.pyw`를 사용하면 콘솔이 없습니다.

GitHub Actions가 main의 `version.py` 변경 또는 수동 실행 시 테스트 → Windows EXE 생성 → GUI 시작 검증 → Release 발행을 진행합니다. 다음 배포에서는 `version.py`, `version_info.txt`, `CHANGELOG.md`, `release_notes.md`, `latest.json`의 버전을 함께 올리세요. 동일 태그의 배포는 덮어쓰지 않습니다. `latest.json`은 외부 연동용 정보이며 앱의 실제 업데이트 판단은 바이너리가 올라온 정식 Release를 기준으로 합니다.
